# OmniQL v0.5.0 Specification

This document outlines the planned features and architectural improvements for OmniQL v0.5.0.

---


code-level suggestions:                                                                                        
  
  ---                                                                                                                               
  1. Non-deterministic fallback driver (engine.go:130)

  // Fallback: return the first registered driver.
  for _, d := range e.drivers {
      return d, nil
  }

  Go map iteration order is random. If two drivers are registered and no explicit Route() is set for a target, which driver handles
  it is unpredictable. Either document that the fallback is intentionally arbitrary, or store a "default driver name" set at
  registration time.

  ---
  2. Schema validator doesn't see inside $or/$and (schema.go:47)

  for field := range query.Filter {
      if _, declared := schema.Fields[field]; !declared { ...

  If a filter is {"$or": [{"undeclared_field": 1}]}, the top-level field is $or, which is not in the schema — so validation rejects
  it (incorrectly). And if you whitelist $or/$and, you lose validation of the sub-fields inside them. The validator needs to recurse
   into logical operator arrays.

  ---
  3. ENGINE_ERROR in FFI is unreachable (ffi.go:79)

  result, err := engine.Execute(...)
  if err != nil {
      return errorJSON("ENGINE_ERROR", err.Error())  // never reached
  }

  engine.Execute never returns a non-nil error — it wraps every failure into OmniJSON.Error. So this ENGINE_ERROR branch is dead
  code. Either engine.Execute should return errors for truly unexpected failures, or this branch should be removed.

  ---
  4. BatchInsert is unreachable from CLI, FFI, and OQL

  BatchInsert is required by the core.Driver interface but:
  - There is no "BATCH_INSERT" action in OQLQuery
  - The engine's Execute method never calls it
  - The CLI and FFI have no corresponding command

  It exists only as a Go-level API. Consider either adding a BATCH_INSERT action to the OQL spec, or moving BatchInsert out of the
  required Driver interface into an optional BatchDriver interface (checked with a type assertion).

  ---
  5. Silent exclusion in field projection (sqlite/driver.go:86, postgres/driver.go:79)

  case float64:
      if v == 1 { include = true }

  Only inclusion (1) is honoured; exclusion (0) is silently ignored — SELECT * is used instead. MongoDB handles this correctly
  natively. For SQL drivers, users who write "fields": {"password": 0} will get no error but still receive the password field. At
  minimum this should return an error or be documented as "SQL drivers support inclusion-only projection."

  ---
  6. UPDATE/DELETE with empty filter hits every row — no warning

  // buildWhere with empty filter returns "", nil, nil

  An UPDATE or DELETE with "filter": {} silently affects every row in the table. A safeguard (e.g. an explicit "filter": {"$all":
  true} token, or a strict-mode check rejecting empty filters on mutating actions) would prevent accidental bulk destructive
  queries.

  ---
  7. Code duplication: buildWhere in SQLite and Postgres

  Both drivers contain ~150 lines of nearly identical filter-building logic, differing only in placeholder style (? vs $N).
  Extracting a shared pkg/drivers/sqlutil package would eliminate the duplication and make it easier to add new SQL operators in one
   place.

## High-Level Goals
- **High-Performance Bulk Operations:** Support for batching 1,000+ records in a single FFI call.
- **Asynchronous Bindings:** Fix event-loop blocking in the TypeScript driver.
- **Advanced Querying:** Support for aggregation, regular expressions, and field exclusion.

---

## 1. Core Engine & Drivers

### 1.1 Batch Operations (`BATCH_INSERT`)
- **Status:** ✅ Implemented in Core Engine and all Drivers (SQLite, Postgres, Mongo).
- **Goal:** Allow language bindings to send an array of documents to be inserted in a single round-trip.
- **Implementation:**
  - `OQLQuery` now includes a `Documents []map[string]interface{}` field.
  - `Driver` interface includes `BatchInsert(ctx, target, docs)`.
  - **SQLite:** Uses prepared statements within a single transaction.
  - **Postgres:** Uses multi-row `VALUES` syntax (`INSERT INTO ... VALUES (...), (...), ...`).
  - **MongoDB:** Uses the native `InsertMany` command.

### 1.2 Aggregation Actions (`AGGREGATE`)
- **New Action:** `AGGREGATE`
- **Goal:** Support basic group-by and summary functions ($sum, $avg, $min, $max).
- **Format:**
  ```json
  {
    "target": "orders",
    "action": "AGGREGATE",
    "pipeline": [
      { "$group": { "_id": "$status", "total": { "$sum": "$price" } } }
    ]
  }
  ```

### 1.3 Field Exclusion
- **Goal:** Support `{"password": 0}` in `QueryOptions.Fields`.
- **Constraint:** All drivers currently assume inclusion-only if fields are present.

## 2. Language Bindings

### 2.1 Non-blocking TypeScript Execution
- **Issue:** `lib.OmniQL_Execute` is a synchronous C call that blocks the main Node.js thread.
- **Solution:** 
  - Migrate to `worker_threads` to offload FFI calls.
  - Or use `ffi-napi`'s asynchronous calling feature (callback-based or Promise-wrapping a native async call).

### 2.2 BatchInsert API in Bindings
Each language binding must expose a `batchInsert` method:
- **Python:** `await engine.batch_insert("users", [doc1, doc2, ...])`
- **Java:** `engine.table("users").batchInsert(List<Map> docs).execute()`
- **C#:** `await engine.Table("users").BatchInsert(IEnumerable<IDictionary> docs).ExecuteAsync()`
- **TypeScript:** `await engine.batchInsert("users", docs[])`

## 3. New Drivers

### 3.1 Redis Driver
- **Target:** Support for key-prefix based queries and basic `FIND`/`INSERT`/`DELETE` on hashes and strings.
- **DSN:** `redis://localhost:6379`

## 4. Testing & Reliability

### 4.1 Cross-Driver Compliance Suite
- A shared JSON file containing 50+ OQL queries and expected results.
- A Go test utility that runs this suite against SQLite, Postgres, and Mongo to ensure absolute parity.

### 4.2 Fuzz Testing
- Fuzzing `pkg/core` JSON parsing and `pkg/ffi` handle management.
