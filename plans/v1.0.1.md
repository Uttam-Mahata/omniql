# v1.0.1 — Post-Release Stabilization

## Theme

Address immediate quality-of-life improvements and minor fixes after the v1.0.0 release. Focus on determinism, developer experience, and test coverage hardening. No new features — pure stabilization.

## Rationale

Every LTS release needs a fast-follow patch to address issues discovered during wider adoption. This release targets three known quality gaps:
1. Non-deterministic WHERE clause output from map iteration (identified in discussions)
2. REPL usability gaps (no tab completion)
3. Fuzz test corpus needs expansion for newly added features

## Deliverable 1: WHERE Clause Determinism Fix

### Problem

`sqlutil.BuildWhere` iterates over `map[string]interface{}` for filter keys. Go map iteration order is non-deterministic, which means:
- The same filter can produce different SQL WHERE clauses across runs
- This makes query caching ineffective
- It makes test assertions fragile (must use `ElementsMatch` style checks)

### Solution

Sort filter keys before iterating in `sqlutil.BuildWhere`. This is the same pattern already used in `BatchInsert` for column ordering.

```go
func BuildWhere(
    filter map[string]interface{},
    placeholder PlaceholderFn,
    quoteIdent func(string) string,
    translateCol func(string) string,
    startIdx int,
) (clause string, args []interface{}, nextIdx int, err error) {
    // Sort filter keys for deterministic output
    keys := make([]string, 0, len(filter))
    for k := range filter {
        keys = append(keys, k)
    }
    sort.Strings(keys)

    // Iterate sorted keys instead of map directly
    for _, key := range keys {
        val := filter[key]
        // ... existing logic
    }
}
```

Also sort keys within `$or` and `$and` sub-filters when they are maps.

## Deliverable 2: Error Message Standardization

### Problem

Error messages from different drivers use inconsistent formats:
- Some prefix with driver name, some don't
- Some include the target name, some don't
- Stack traces leak through in some cases

### Solution

Create a helper function in `pkg/core/errors.go` for consistent error wrapping:

```go
// DriverError creates a standardized error message for driver-level errors.
func DriverError(driver, target, action, message string) error {
    return fmt.Errorf("[%s] %s on %q: %s", driver, action, target, message)
}
```

Update each driver to use this helper for error returns from `Execute` and `BatchInsert`.

## Deliverable 3: REPL Tab Completion

### Feature

Add context-aware tab completion to the interactive REPL (`cmd/omniql/repl.go`):

1. **Dot-command completion**: Typing `.` + Tab suggests `.help`, `.drivers`, `.routes`, `.exit`
2. **Action completion**: Inside a JSON body, typing `"action": "` + Tab suggests `FIND`, `INSERT`, `UPDATE`, `DELETE`, `COUNT`, `BATCH_INSERT`
3. **Target completion**: Inside a JSON body, typing `"target": "` + Tab suggests known route targets from the engine

### Implementation

The `liner` library supports a `SetCompleter` callback:

```go
func (r *repl) setupCompleter() {
    r.line.SetCompleter(func(line string) []string {
        var completions []string

        // Dot-command completion
        if strings.HasPrefix(line, ".") {
            for _, cmd := range []string{".help", ".drivers", ".routes", ".exit"} {
                if strings.HasPrefix(cmd, line) {
                    completions = append(completions, cmd)
                }
            }
            return completions
        }

        // Action completion
        if strings.Contains(line, `"action"`) && strings.HasSuffix(strings.TrimSpace(line), `"`) {
            for _, action := range []string{"FIND", "INSERT", "UPDATE", "DELETE", "COUNT", "BATCH_INSERT"} {
                completions = append(completions, action)
            }
        }

        // Target completion from routes
        if strings.Contains(line, `"target"`) && strings.HasSuffix(strings.TrimSpace(line), `"`) {
            for target := range r.engine.Routes() {
                completions = append(completions, target)
            }
        }

        return completions
    })
}
```
