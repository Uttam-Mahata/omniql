# v1.0.3 — AI-Agent Gateway & Observability

## Theme

Transform OmniQL into a first-class AI-agent data gateway by implementing an MCP (Model Context Protocol) server, adding OpenTelemetry distributed tracing, and introducing health-check endpoints. This version positions OmniQL as the bridge between AI agents and any database.

## Rationale

- **MCP Server**: AI agents (Claude, GPT, etc.) using the Model Context Protocol need structured tools to interact with databases. OmniQL's unified query layer is a natural fit — one tool definition covers all databases.
- **OpenTelemetry**: Production observability is non-negotiable. Tracing each query from the language binding through FFI, engine routing, driver execution, and back enables performance debugging and SLA monitoring.
- **Health Checks**: Multi-driver deployments need per-driver health visibility for orchestration (Kubernetes probes, load balancers).

## Deliverable 1: MCP Server (`omniql mcp`)

### Overview

The MCP server runs as a subprocess (stdio transport) and exposes OmniQL's query engine as MCP tools. AI agents connect via the Model Context Protocol and can query any routed database.

### CLI Integration (`cmd/omniql/main.go`)

```bash
# Start MCP server (stdio transport)
omniql mcp -config omniql.yaml

# With explicit driver
omniql mcp -driver sqlite -dsn ./data.db
```

The `mcp` subcommand is detected before `flag.Parse()`, following the same pattern as the `shell` subcommand.

### MCP Tools Exposed

#### `omniql_query`

Execute any OQL query against the configured engine.

```json
{
  "name": "omniql_query",
  "description": "Execute a database query using OmniQL's unified query language. Supports FIND, INSERT, UPDATE, DELETE, COUNT, and BATCH_INSERT across all configured databases.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "target":    { "type": "string", "description": "Collection/table/index name" },
      "action":    { "type": "string", "enum": ["FIND", "INSERT", "BATCH_INSERT", "UPDATE", "DELETE", "COUNT"] },
      "filter":    { "type": "object", "description": "MongoDB-style filter operators" },
      "document":  { "type": "object", "description": "Data for INSERT/UPDATE" },
      "documents": { "type": "array", "description": "Data for BATCH_INSERT" },
      "options":   { "type": "object", "description": "limit, skip, sort, fields" }
    },
    "required": ["target", "action"]
  }
}
```

#### `omniql_schema`

List all registered schemas and routes.

```json
{
  "name": "omniql_schema",
  "description": "List all available database targets, their schemas, and which driver handles each target.",
  "inputSchema": { "type": "object", "properties": {} }
}
```

#### `omniql_health`

Check driver health status.

```json
{
  "name": "omniql_health",
  "description": "Check the health of all registered database drivers.",
  "inputSchema": { "type": "object", "properties": {} }
}
```

### Implementation

Use the `github.com/mark3labs/mcp-go` library (Go MCP SDK) which provides stdio server transport.

```go
package main

import (
    "github.com/mark3labs/mcp-go/mcp"
    "github.com/mark3labs/mcp-go/server"
)

func runMCPMode() {
    // Parse config, build engine (same as shell mode)
    engine := buildEngineFromConfig()

    s := server.NewMCPServer("omniql", "1.0.3",
        server.WithToolCapabilities(true),
    )

    // Register tools
    s.AddTool(mcp.NewTool("omniql_query", ...), handleQuery(engine))
    s.AddTool(mcp.NewTool("omniql_schema", ...), handleSchema(engine))
    s.AddTool(mcp.NewTool("omniql_health", ...), handleHealth(engine))

    // Start stdio transport
    server.ServeStdio(s)
}
```

## Deliverable 2: OpenTelemetry Tracing

### Trace Points

Instrument the following spans in the query pipeline:

```
omniql.execute (root span)
├── omniql.schema.validate
├── omniql.route.select
├── omniql.driver.execute (attributes: driver, target, action)
│   └── db.query (driver-specific: SQL text or MongoDB command)
└── omniql.response.marshal
```

### Engine Middleware Pattern

Add an optional `WithTracing()` engine option that wraps the execute pipeline:

```go
// WithTracing enables OpenTelemetry span creation for every query.
func WithTracing(tp trace.TracerProvider) EngineOption {
    return func(e *Engine) {
        e.tracerProvider = tp
    }
}
```

When tracing is enabled, `Engine.Execute` creates spans around each pipeline step. Each span includes attributes:
- `omniql.target` — the collection/table name
- `omniql.action` — FIND, INSERT, etc.
- `omniql.driver` — which driver handled the query
- `omniql.returned` — number of rows returned
- `omniql.error` — error code if failed

### Driver-Level Instrumentation

Each driver wraps its native database call in a child span:
- SQL drivers: span attribute `db.statement` with the parameterized SQL (no argument values for security)
- MongoDB: span attribute `db.operation` with the BSON command name
- Redis: span attribute `db.operation` with the Redis command (GET, SET, SCAN, etc.)
- Elasticsearch: span attribute `db.operation` with the HTTP method + endpoint
- InfluxDB: span attribute `db.operation` with the Flux query or write operation

## Deliverable 3: Health Check System

### Engine Health API (`pkg/core/engine.go`)

```go
// DriverHealth represents the health status of a single driver.
type DriverHealth struct {
    Driver  string `json:"driver"`
    Healthy bool   `json:"healthy"`
    Latency string `json:"latency"` // e.g., "2.3ms"
    Error   string `json:"error,omitempty"`
}

// Health pings all registered drivers and returns their status.
func (e *Engine) Health(ctx context.Context) []DriverHealth
```

Implementation calls `driver.Ping(ctx)` for each registered driver in parallel (using goroutines), collects results with timing, and returns the slice.

### CLI Health Command

```bash
# Check health of all configured drivers
omniql health -config omniql.yaml
```

Output (JSON):
```json
[
  { "driver": "postgres", "healthy": true, "latency": "1.2ms" },
  { "driver": "redis", "healthy": true, "latency": "0.3ms" },
  { "driver": "elasticsearch", "healthy": false, "latency": "5001ms", "error": "connection refused" }
]
```
