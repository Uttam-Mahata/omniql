# v1.0.5 — Driver Expansion: DynamoDB, CouchDB, Firestore

## Theme

Expand OmniQL's database coverage with three new drivers targeting the most widely used managed/cloud-native databases: AWS DynamoDB, Apache CouchDB, and Google Cloud Firestore. This brings the total driver count to 12 and covers the major cloud providers' primary NoSQL offerings.

## Rationale

- **DynamoDB** is the default database for AWS-native applications. Millions of production workloads run on it. OmniQL without DynamoDB support is invisible to the AWS ecosystem.
- **CouchDB** is the most widely deployed open-source document database after MongoDB. It's used heavily in offline-first/mobile applications (via PouchDB) and edge computing.
- **Firestore** is Google Cloud's primary NoSQL database and the default for Firebase. It's the entry point for most mobile/web developers building on GCP.
- Together with the existing drivers (SQLite, Postgres, MySQL, SQL Server, MongoDB, Redis, Elasticsearch, InfluxDB, Neo4j), this gives OmniQL coverage across **AWS + GCP + Azure + self-hosted** and across **5 paradigms** (relational, document, key-value, time-series, graph, search).

## Deliverable 1: DynamoDB Driver (`pkg/drivers/dynamodb/`)

### OQL → DynamoDB Translation

| OQL Action | DynamoDB API |
|---|---|
| `FIND` with id filter | `GetItem` |
| `FIND` with other filters | `Scan` with `FilterExpression` |
| `INSERT` | `PutItem` |
| `UPDATE` | `UpdateItem` with `UpdateExpression` |
| `DELETE` | `DeleteItem` |
| `COUNT` | `Scan` with `Select: COUNT` |
| `BATCH_INSERT` | `BatchWriteItem` (25-item chunks) |

### OQL Filter → DynamoDB FilterExpression

| OQL Operator | DynamoDB Expression |
|---|---|
| `{"name": "Alice"}` / `$eq` | `#name = :v1` |
| `$ne` | `#name <> :v1` |
| `$gt` / `$gte` | `#age > :v1` / `#age >= :v1` |
| `$lt` / `$lte` | `#price < :v1` / `#price <= :v1` |
| `$in` | Uses `OR` chain: `#status = :v1 OR #status = :v2` |
| `$nin` | Uses `AND NOT` chain |
| `$or` | Parenthesized `OR` groups |
| `$and` | Parenthesized `AND` groups |

DynamoDB uses **expression attribute names** (`#name`) and **expression attribute values** (`:v1`) to avoid reserved-word conflicts — similar to parameterized SQL.

### Driver Implementation

```go
package dynamodb

import (
    "context"
    "fmt"

    "github.com/aws/aws-sdk-go-v2/config"
    "github.com/aws/aws-sdk-go-v2/service/dynamodb"
    "github.com/Uttam-Mahata/omniql/pkg/core"
)

type Driver struct {
    client *dynamodb.Client
    region string
}

// New creates a DynamoDB driver.
// Uses standard AWS credential chain (env vars, ~/.aws/credentials, IAM role).
// region: AWS region (e.g., "us-east-1")
// endpoint: optional override for local testing (e.g., "http://localhost:8000" for DynamoDB Local)
func New(region string, endpoint string) (*Driver, error) {
    cfg, err := config.LoadDefaultConfig(context.Background(),
        config.WithRegion(region),
    )
    if err != nil {
        return nil, fmt.Errorf("dynamodb config: %w", err)
    }
    opts := []func(*dynamodb.Options){}
    if endpoint != "" {
        opts = append(opts, func(o *dynamodb.Options) {
            o.BaseEndpoint = &endpoint
        })
    }
    client := dynamodb.NewFromConfig(cfg, opts...)
    return &Driver{client: client, region: region}, nil
}

func (d *Driver) Name() string { return "dynamodb" }

func (d *Driver) Execute(ctx context.Context, query core.OQLQuery) ([]map[string]interface{}, int64, error) {
    // Dispatch to getItem/scan/putItem/updateItem/deleteItem based on query.Action
}

func (d *Driver) BatchInsert(ctx context.Context, target string, docs []map[string]interface{}) ([]map[string]interface{}, error) {
    // BatchWriteItem in chunks of 25 (DynamoDB limit)
}

func (d *Driver) Ping(ctx context.Context) error {
    _, err := d.client.ListTables(ctx, &dynamodb.ListTablesInput{Limit: aws.Int32(1)})
    return err
}

func (d *Driver) Close() error { return nil } // AWS SDK client has no Close
```

### DynamoDB-Specific Considerations

- **Primary Key Required**: DynamoDB tables have a partition key (and optional sort key). INSERT must include the primary key. The driver infers key schema from the table on first access and caches it.
- **Scan vs Query**: `FIND` with only the partition key in the filter uses `GetItem` (fast). Anything else falls back to `Scan` (full table scan) with `FilterExpression`. This is a known DynamoDB limitation — the driver doesn't hide it, consumers should be aware.
- **BatchWriteItem Limit**: DynamoDB allows max 25 items per batch. `BatchInsert` chunks automatically.
- **No native $in**: DynamoDB doesn't have an `IN` operator in filter expressions. The driver expands `$in` to an `OR` chain.

## Deliverable 2: CouchDB Driver (`pkg/drivers/couchdb/`)

### OQL → CouchDB Translation

CouchDB uses an HTTP REST API with Mango queries (JSON-based, similar to MongoDB).

| OQL Action | CouchDB API |
|---|---|
| `FIND` | `POST /{db}/_find` with Mango selector |
| `INSERT` | `POST /{db}` with JSON body |
| `UPDATE` | `GET /{db}/{id}` → merge → `PUT /{db}/{id}` (requires `_rev`) |
| `DELETE` | `DELETE /{db}/{id}?rev={_rev}` |
| `COUNT` | `POST /{db}/_find` with `limit: 0` + `execution_stats: true` |
| `BATCH_INSERT` | `POST /{db}/_bulk_docs` |

### OQL Filter → Mango Selector

CouchDB's Mango query language is nearly identical to MongoDB's:

| OQL Operator | Mango Selector |
|---|---|
| `$eq` | `{ "field": { "$eq": value } }` |
| `$ne` | `{ "field": { "$ne": value } }` |
| `$gt` / `$gte` | `{ "field": { "$gt": value } }` |
| `$lt` / `$lte` | `{ "field": { "$lt": value } }` |
| `$in` | `{ "field": { "$in": [values] } }` |
| `$nin` | `{ "field": { "$nin": [values] } }` |
| `$or` | `{ "$or": [selectors] }` |
| `$and` | `{ "$and": [selectors] }` |

This is essentially a 1:1 pass-through — CouchDB Mango uses the same operator syntax as OQL.

### Driver Implementation

```go
package couchdb

import (
    "context"
    "fmt"
    "net/http"

    "github.com/Uttam-Mahata/omniql/pkg/core"
)

type Driver struct {
    baseURL    string
    httpClient *http.Client
    dbName     string
}

// New creates a CouchDB driver.
// url: CouchDB server URL (e.g., "http://admin:password@localhost:5984")
// dbName: database name
func New(url, dbName string) (*Driver, error) {
    return &Driver{
        baseURL:    url,
        httpClient: &http.Client{},
        dbName:     dbName,
    }, nil
}

func (d *Driver) Name() string { return "couchdb" }
```

### CouchDB-Specific Considerations

- **Revision System**: CouchDB uses `_rev` for optimistic concurrency. UPDATE requires fetching the current `_rev` first, then PUT with the new `_rev`. The driver handles this internally (GET → merge → PUT).
- **No native COUNT**: CouchDB Mango has no dedicated count. The driver uses `_find` with `execution_stats: true` to get total docs, or `_all_docs` with `limit=0`.
- **ID Field**: CouchDB uses `_id` as the document identifier. The driver maps `id` in OQL to `_id` transparently.
- **No raw HTTP dependency**: Uses `net/http` from stdlib — no third-party CouchDB client needed.

## Deliverable 3: Firestore Driver (`pkg/drivers/firestore/`)

### OQL → Firestore Translation

| OQL Action | Firestore API |
|---|---|
| `FIND` with id filter | `Collection.Doc(id).Get()` |
| `FIND` with filters | `Collection.Where(...).Documents()` |
| `INSERT` | `Collection.Doc(id).Set()` or `Collection.Add()` (auto-ID) |
| `UPDATE` | `Collection.Doc(id).Update()` with field paths |
| `DELETE` | `Collection.Doc(id).Delete()` |
| `COUNT` | `Collection.Where(...).Count().Get()` (Firestore Count aggregation) |
| `BATCH_INSERT` | `WriteBatch` with multiple `Set` operations (max 500 per batch) |

### OQL Filter → Firestore Where Clauses

| OQL Operator | Firestore `Where` |
|---|---|
| `$eq` | `.Where("field", "==", value)` |
| `$ne` | `.Where("field", "!=", value)` |
| `$gt` / `$gte` | `.Where("field", ">", value)` / `.Where("field", ">=", value)` |
| `$lt` / `$lte` | `.Where("field", "<", value)` / `.Where("field", "<=", value)` |
| `$in` | `.Where("field", "in", []value)` |
| `$nin` | `.Where("field", "not-in", []value)` |
| `$or` | Firestore `Or` filter (requires composite index) |
| `$and` | Chained `.Where()` calls (implicit AND) |

### Driver Implementation

```go
package firestore

import (
    "context"
    "fmt"

    "cloud.google.com/go/firestore"
    "github.com/Uttam-Mahata/omniql/pkg/core"
)

type Driver struct {
    client    *firestore.Client
    projectID string
}

// New creates a Firestore driver.
// projectID: GCP project ID
// Uses Application Default Credentials (ADC) — set GOOGLE_APPLICATION_CREDENTIALS or run on GCE/GKE.
func New(ctx context.Context, projectID string) (*Driver, error) {
    client, err := firestore.NewClient(ctx, projectID)
    if err != nil {
        return nil, fmt.Errorf("firestore: %w", err)
    }
    return &Driver{client: client, projectID: projectID}, nil
}

func (d *Driver) Name() string { return "firestore" }
```

### Firestore-Specific Considerations

- **Collection = Target**: OQL `target` maps directly to a Firestore collection name.
- **Document ID**: Firestore documents have an auto-generated ID or a caller-supplied one. If OQL document contains `id` or `_id`, it's used as the document ID. Otherwise, Firestore auto-generates one.
- **Composite Indexes**: Firestore requires composite indexes for queries with multiple inequality filters or `$or`. The driver doesn't create indexes — consumers must set them up in their Firebase console/config. The driver returns the Firestore error message (which includes the index creation URL) when an index is missing.
- **WriteBatch Limit**: Firestore allows max 500 operations per batch. `BatchInsert` chunks automatically.
- **No JOIN/relationship**: Firestore is document-only. This is fine — OmniQL doesn't promise cross-driver joins.
- **Authentication**: Uses GCP Application Default Credentials. For local dev, use the Firestore emulator.
