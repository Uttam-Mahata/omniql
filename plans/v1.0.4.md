# v1.0.4 — Driver Expansion: InfluxDB, Cassandra, SurrealDB, TiDB

## Theme

Add four more database drivers: InfluxDB (time-series), Apache Cassandra (wide-column), SurrealDB (multi-model), and TiDB (distributed SQL). This broadens OmniQL into the time-series and distributed database space.

## Rationale

- **InfluxDB** is the most widely deployed open-source time-series database. IoT, monitoring, and financial applications all need time-windowed queries. OQL maps to Flux queries and the Write API.
- **Cassandra** is the go-to database for massive write throughput and global distribution. Used by Netflix, Apple, Instagram. No unified access layer is complete without it.
- **SurrealDB** is a multi-model database (document + graph + relational in one) gaining rapid adoption. Its SQL-like query language maps well to OQL, and supporting it positions OmniQL in the "next-gen database" space.
- **TiDB** is a MySQL-compatible distributed SQL database. Since OmniQL already has a MySQL driver, TiDB support is mostly about verifying compatibility and handling TiDB-specific behaviors (distributed transactions, placement rules). It's a low-effort, high-value addition.
- Together with v1.0.5 (DynamoDB, CouchDB, Firestore), this brings OmniQL to **15 drivers**.

## Deliverable 1: Cassandra Driver (`pkg/drivers/cassandra/`)

### OQL → CQL Translation

Cassandra uses CQL (Cassandra Query Language), which looks like SQL but has significant restrictions.

| OQL Action | CQL |
|---|---|
| `FIND` | `SELECT * FROM target WHERE ... [LIMIT n]` |
| `INSERT` | `INSERT INTO target (cols) VALUES (vals)` |
| `UPDATE` | `UPDATE target SET col=val WHERE ...` |
| `DELETE` | `DELETE FROM target WHERE ...` |
| `COUNT` | `SELECT COUNT(*) FROM target WHERE ...` |
| `BATCH_INSERT` | CQL `BEGIN BATCH ... APPLY BATCH` |

### OQL Filter → CQL WHERE

| OQL Operator | CQL Expression |
|---|---|
| `$eq` / bare value | `col = ?` |
| `$gt` / `$gte` | `col > ?` / `col >= ?` |
| `$lt` / `$lte` | `col < ?` / `col <= ?` |
| `$in` | `col IN ?` |
| `$ne` | Not natively supported — return error |
| `$nin` | Not natively supported — return error |
| `$or` | Not natively supported — return error |
| `$and` | Chained `AND` (implicit in CQL WHERE) |

Cassandra has strict query restrictions — you can only filter on primary key columns and indexed columns. The driver does not hide this; it passes the CQL to Cassandra and returns the error if the query is invalid.

### Driver Implementation

```go
package cassandra

import (
    "context"
    "fmt"

    "github.com/gocql/gocql"
    "github.com/Uttam-Mahata/omniql/pkg/core"
)

type Driver struct {
    session *gocql.Session
}

// New creates a Cassandra driver.
// hosts: comma-separated contact points (e.g., "127.0.0.1,127.0.0.2")
// keyspace: Cassandra keyspace name
func New(hosts string, keyspace string) (*Driver, error) {
    cluster := gocql.NewCluster(splitHosts(hosts)...)
    cluster.Keyspace = keyspace
    cluster.Consistency = gocql.Quorum
    session, err := cluster.CreateSession()
    if err != nil {
        return nil, fmt.Errorf("cassandra: %w", err)
    }
    return &Driver{session: session}, nil
}

func (d *Driver) Name() string { return "cassandra" }

func (d *Driver) Ping(ctx context.Context) error {
    return d.session.Query("SELECT now() FROM system.local").WithContext(ctx).Exec()
}

func (d *Driver) Close() error {
    d.session.Close()
    return nil
}
```

### CQL Builder

CQL is SQL-like, so it can use a simplified version of the SQL pattern but with `?` placeholders (positional, like SQLite/MySQL):

```go
// buildWhere converts OQL filter to CQL WHERE clause.
// Only supports $eq, $gt, $gte, $lt, $lte, $in, $and.
// Returns error for unsupported operators ($ne, $nin, $or).
func buildWhere(filter map[string]interface{}) (clause string, args []interface{}, err error)
```

Note: Does NOT use `sqlutil.BuildWhere` because CQL has different restrictions (no OR, no subqueries, no arbitrary column filtering). A separate builder is cleaner than trying to force CQL into the SQL utility.

### Cassandra-Specific Considerations

- **Primary Key Restrictions**: Cassandra requires the partition key in most WHERE clauses. The driver doesn't work around this — it passes the query and lets Cassandra return the error.
- **No $ne/$nin/$or**: CQL doesn't support these. The driver returns `UNSUPPORTED_OPERATOR` error.
- **ALLOW FILTERING**: The driver does NOT inject `ALLOW FILTERING` automatically. This is a dangerous Cassandra anti-pattern that causes full cluster scans. If the consumer needs it, they should use raw CQL.
- **Consistency**: Defaults to `QUORUM`. Consumers configure this when creating the `gocql.Cluster` and pass it in (future: accept `*gocql.Session` directly, like Postgres accepts `*sql.DB`).

## Deliverable 2: SurrealDB Driver (`pkg/drivers/surrealdb/`)

### OQL → SurrealQL Translation

SurrealDB uses SurrealQL, a SQL-like language with document/graph extensions.

| OQL Action | SurrealQL |
|---|---|
| `FIND` | `SELECT * FROM target WHERE ... LIMIT n START n` |
| `INSERT` | `CREATE target CONTENT { ... }` |
| `UPDATE` | `UPDATE target SET col = val WHERE ...` |
| `DELETE` | `DELETE target WHERE ...` |
| `COUNT` | `SELECT count() AS count FROM target WHERE ... GROUP ALL` |
| `BATCH_INSERT` | `INSERT INTO target [ {...}, {...} ]` |

### OQL Filter → SurrealQL WHERE

| OQL Operator | SurrealQL Expression |
|---|---|
| `$eq` / bare value | `col = $p1` |
| `$ne` | `col != $p1` |
| `$gt` / `$gte` | `col > $p1` / `col >= $p1` |
| `$lt` / `$lte` | `col < $p1` / `col <= $p1` |
| `$in` | `col IN $p1` |
| `$nin` | `col NOT IN $p1` |
| `$or` | `(cond1) OR (cond2)` |
| `$and` | `(cond1) AND (cond2)` |

SurrealQL supports all OQL operators natively — full feature parity.

### Driver Implementation

```go
package surrealdb

import (
    "context"
    "fmt"

    sdb "github.com/surrealdb/surrealdb.go/v2"
    "github.com/Uttam-Mahata/omniql/pkg/core"
)

type Driver struct {
    db *sdb.DB
}

// New creates a SurrealDB driver.
// url: WebSocket endpoint (e.g., "ws://localhost:8000/rpc")
// namespace: SurrealDB namespace
// database: SurrealDB database
// user/pass: authentication credentials
func New(url, namespace, database, user, pass string) (*Driver, error) {
    db, err := sdb.New(url)
    if err != nil {
        return nil, fmt.Errorf("surrealdb connect: %w", err)
    }
    if _, err := db.Signin(map[string]interface{}{
        "user": user, "pass": pass,
    }); err != nil {
        return nil, fmt.Errorf("surrealdb signin: %w", err)
    }
    if _, err := db.Use(namespace, database); err != nil {
        return nil, fmt.Errorf("surrealdb use: %w", err)
    }
    return &Driver{db: db}, nil
}

func (d *Driver) Name() string { return "surrealdb" }
```

### SurrealDB-Specific Considerations

- **Record IDs**: SurrealDB uses `target:id` format for record identifiers (e.g., `users:alice`). The driver handles this — on INSERT, if the document has `id`, it uses `CREATE target:id CONTENT {...}`. On FIND, the returned `id` is the SurrealDB record ID string.
- **Full Operator Support**: SurrealQL supports all OQL operators including `$or`, `$in`, `$nin`. This is the easiest driver to implement after the SQL drivers.
- **Pagination**: `LIMIT n START n` (equivalent to SQL `LIMIT n OFFSET n`).
- **Parameters**: SurrealQL supports `$param` style named parameters — similar to Neo4j.

## Deliverable 3: TiDB Driver (`pkg/drivers/tidb/`)

### Approach

TiDB is wire-compatible with MySQL. The existing MySQL driver (`pkg/drivers/mysql/`) works with TiDB out of the box — same DSN format, same SQL dialect, same `?` placeholders, same backtick quoting.

The TiDB driver is a **thin wrapper** around the MySQL driver that:
1. Returns `"tidb"` from `Name()` (so routes can distinguish TiDB from MySQL)
2. Uses the same `go-sql-driver/mysql` underneath
3. Adds TiDB-specific Ping validation (checks `SELECT tidb_version()`)

```go
package tidb

import (
    "context"
    "database/sql"
    "fmt"

    _ "github.com/go-sql-driver/mysql"
    "github.com/Uttam-Mahata/omniql/pkg/core"
    drvmysql "github.com/Uttam-Mahata/omniql/pkg/drivers/mysql"
)

// Driver wraps the MySQL driver for TiDB compatibility.
type Driver struct {
    inner *drvmysql.Driver
    db    *sql.DB
}

// New creates a TiDB driver. DSN format is identical to MySQL:
// "user:password@tcp(host:4000)/dbname?parseTime=true"
// (TiDB default port is 4000, not 3306)
func New(dsn string) (*Driver, error) {
    inner, err := drvmysql.New(dsn)
    if err != nil {
        return nil, fmt.Errorf("tidb: %w", err)
    }
    db, err := sql.Open("mysql", dsn)
    if err != nil {
        return nil, fmt.Errorf("tidb open: %w", err)
    }
    return &Driver{inner: inner, db: db}, nil
}

func (d *Driver) Name() string { return "tidb" }

func (d *Driver) Execute(ctx context.Context, query core.OQLQuery) ([]map[string]interface{}, int64, error) {
    return d.inner.Execute(ctx, query)
}

func (d *Driver) BatchInsert(ctx context.Context, target string, docs []map[string]interface{}) ([]map[string]interface{}, error) {
    return d.inner.BatchInsert(ctx, target, docs)
}

func (d *Driver) Ping(ctx context.Context) error {
    // Verify it's actually TiDB, not plain MySQL
    var version string
    err := d.db.QueryRowContext(ctx, "SELECT tidb_version()").Scan(&version)
    if err != nil {
        return fmt.Errorf("tidb ping: %w (is this actually a TiDB instance?)", err)
    }
    return nil
}

func (d *Driver) Close() error {
    d.db.Close()
    return d.inner.Close()
}
```

### Why a Separate Driver?

- **Routing**: Consumers can route `analytics → tidb` and `users → mysql` in the same engine. Without a separate driver name, both would show as `"mysql"` in OmniJSON metadata.
- **Future**: TiDB has features MySQL doesn't (distributed transactions, placement rules). A separate driver allows adding TiDB-specific optimizations later without polluting the MySQL driver.
- **Minimal Code**: The driver is ~50 lines — just delegation + name.
